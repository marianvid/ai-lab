On the ranking, Marian's reasoning is the one to keep: *the purpose is to help
someone choosing hardware clarify a decision.* NVIDIA against Intel B70 against
Radeon R9700 against Tenstorrent — cards with comparable silicon whose software
ecosystems are far apart, which is the difference between a tool that works and
an evening of fighting.

## What makes this worth publishing

Not the leaderboard alone; that ages in a month. Four things last:

1. **A harness anyone can run on their own card.** The comparison problem in this
   field is that no two reviews measure the same thing — see the incomparable
   vendor numbers in `06-OPEN-QUESTIONS.md`. A fixed, documented test suite turns
   "my card got X" into a contribution. *Have a B70? Run the three tests, send a
   pull request with your column.*
2. **A real bug, fully diagnosed.** vLLM 0.27.1 cannot load Gemma-4. Two defects,
   root cause traced to a `RuntimeError` that `getattr` cannot catch, a patch, and
   verification that the patched model computes correctly rather than merely
   starting.
3. **The pruning curve.** 0.957 → 0.931 → 0.900 → 0.864, monotonic.
4. **A survey of engines that do not work**, with the reason for each. Anyone
   buying a workstation Blackwell card expecting to run TensorRT-LLM should read
   `08-ENGINE-MODEL-SUPPORT.md` before spending the money. The headline is that
   **no C++ engine supports the card's native format**.
5. **The five ways the measurements lied.** `04-PITFALLS.md`. This is the part
   with the longest shelf life: a ranking is obsolete next quarter, but "how to
   avoid fooling yourself while benchmarking" stays useful.

## Proposed repository layout

Largely what is already here, plus what a stranger needs.

```
README.md              what it is, headline results, how to contribute a column
LICENCE                permissive for harness/results; separate note for the corpus
CONTRIBUTING.md        how to run the suite and submit your card's numbers
docs/
  methodology.md       from 01-METHODOLOGY.md
  results.md           from 02-RESULTS.md
  findings.md          from 03-FINDINGS.md
  pitfalls.md          from 04-PITFALLS.md
  vllm-gemma4-bug.md   from 05-VLLM-GEMMA4-BUG.md
  hardware.md          the cross-vendor comparison, with its caveats stated loudly
benchmark/             scripts, prompts, goldensets, reference answers
results/               one file per (card, model, test) — this is what grows
```

**Before publishing:** strip the internal addresses, the SSH key path and the
container specifics from anything under `docs/`. They belong in
`00-CONTEXT.md`, which stays private.

## Article plan

Short, on LinkedIn, pointing at the repository. Spine, in order:

1. The setup, in one paragraph: one 32 GB card, three real jobs.
2. **The counter-intuitive result first** — the engine mattered more than the
   model. ×10 to ×17 from continuous batching, against ×1.4.
3. The ranking, with prices, because that is what the reader came for.
4. What pruning costs, with the curve.
5. The bug, briefly, as evidence the ecosystem argument is not abstract: the
   software gap between vendors is real, and even the leader has holes.
6. The pitfalls, as the closing argument for why the harness is the deliverable.
7. Link.

Tone: measured, no superlatives, numbers with their caveats attached. Every claim
traceable to a file in the repository.
